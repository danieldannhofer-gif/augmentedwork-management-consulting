# Client Deliverables

Create professional, high-quality client deliverables that communicate insights, recommendations, and value effectively. Develop reports, presentations, analyses, and other outputs that meet client expectations and drive action.

## Trigger

User runs `/management-consulting-client-deliverables` or asks to create a client deliverable, report, presentation, or analysis.

## Inputs

Gather the following from the user:

1. **Deliverable type** — what needs to be created:
   - Executive summary
   - Full report
   - Presentation deck
   - Analysis document
   - Recommendations memo
   - Dashboard or data visualization
   - Workshop materials
   - Implementation plan
   - Business case
   - Financial model

2. **Audience** — who will receive the deliverable:
   - Executive team
   - Board of directors
   - Client stakeholders
   - Internal team
   - Specific department
   - External partners

3. **Purpose** — what the deliverable should achieve:
   - Inform decision-making
   - Present findings
   - Recommend actions
   - Request approval
   - Secure funding
   - Demonstrate value
   - Support a business case

4. **Content** — what should be included:
   - Data and analysis
   - Findings and insights
   - Recommendations
   - Supporting evidence
   - Appendices

5. **Format** — preferred format:
   - PDF document
   - PowerPoint/Google Slides presentation
   - Excel/Google Sheets spreadsheet
   - Word/Google Docs document
   - Interactive dashboard
   - Email summary

6. **Constraints**:
   - Length (pages, slides, words)
   - Deadline
   - Brand guidelines
   - Confidentiality requirements

## Deliverable Development Process

### Step 1: Define Deliverable Scope

Clarify the purpose, audience, and key messages:

**Scope Definition Template**:
```
**Deliverable**: [Name/Type]
**Purpose**: [What it should achieve]
**Audience**: [Primary and secondary audiences]
**Key Message**: [Main takeaway]
**Success Criteria**: [How success will be measured]

**Content Outline**:
1. [Section 1]
2. [Section 2]
3. [Section 3]

**Format**: [PDF/PPT/XLS/DOC]
**Length**: [Number of pages/slides/words]
**Deadline**: [Date]
**Owner**: [Name]
```

**Key Questions**:
- What is the single most important message?
- What does the audience already know?
- What do they need to know?
- What action should they take?
- What format will be most effective?

### Step 2: Structure the Deliverable

**Effective Deliverable Structure**:

1. **Executive Summary** (for reports) or **Title Slide** (for presentations)
   - Key findings or recommendations
   - Bottom line up front
   - What the audience needs to know

2. **Introduction/Background**
   - Context and objectives
   - Methodology or approach
   - Scope and limitations

3. **Findings/Analysis**
   - Data and insights
   - Key observations
   - Trends and patterns

4. **Recommendations**
   - Actionable next steps
   - Prioritized by impact and feasibility
   - Implementation considerations

5. **Appendices** (if needed)
   - Supporting data
   - Detailed analysis
   - References

**Structure by Deliverable Type**:

**Report Structure**:
1. Executive Summary
2. Introduction
3. Methodology
4. Findings
5. Analysis
6. Recommendations
7. Appendices

**Presentation Structure**:
1. Title Slide
2. Agenda
3. Executive Summary
4. Background
5. Findings
6. Recommendations
7. Next Steps
8. Q&A

**Analysis Structure**:
1. Objective
2. Approach
3. Data
4. Analysis
5. Insights
6. Implications

### Step 3: Develop Key Messages

**Message Development**:
- **Primary Message**: The single most important takeaway
- **Supporting Messages**: 3-5 key points that support the primary message
- **Proof Points**: Data, evidence, or examples that validate the messages
- **Call to Action**: What the audience should do next

**Message Framework**:
```
**Primary Message**: [One sentence summary]

**Supporting Messages**:
1. [Message 1] — [Proof point]
2. [Message 2] — [Proof point]
3. [Message 3] — [Proof point]

**Call to Action**: [What to do next]
```

**Message Tips**:
- Keep it simple and clear
- Focus on insights, not data
- Use the audience's language
- Make it actionable
- Prioritize by importance

### Step 4: Create Content

**Content Development**:

1. **Gather Data and Insights**
   - Collect relevant data
   - Identify key insights
   - Validate findings
   - Source evidence

2. **Organize Information**
   - Logical flow
   - Clear hierarchy
   - Easy to navigate
   - Visually appealing

3. **Write Effectively**
   - Clear and concise
   - Active voice
   - Professional tone
   - Consistent style

4. **Design for Impact**
   - Visual hierarchy
   - Consistent branding
   - Appropriate visuals
   - Easy to scan

**Content Quality Checklist**:
- [ ] Clear purpose and objective
- [ ] Logical structure and flow
- [ ] Accurate data and analysis
- [ ] Actionable insights and recommendations
- [ ] Professional tone and style
- [ ] Consistent formatting
- [ ] Proper grammar and spelling
- [ ] Appropriate visuals
- [ ] Correct branding
- [ ] Meets length requirements

### Step 5: Design and Format

**Design Principles**:

1. **Visual Hierarchy**
   - Most important information first
   - Use headings, subheadings, and bullet points
   - Highlight key findings
   - Use consistent formatting

2. **Brand Consistency**
   - Use company colors and fonts
   - Include company logo
   - Follow brand guidelines
   - Maintain professional appearance

3. **Readability**
   - Use sufficient white space
   - Keep paragraphs short
   - Use bullet points and numbered lists
   - Avoid walls of text
   - Use appropriate font sizes

4. **Visuals**
   - Use charts and graphs for data
   - Include relevant images
   - Use icons for emphasis
   - Keep visuals simple and clear
   - Ensure visuals are high-quality

**Design Tools**:
- **Documents**: Microsoft Word, Google Docs, Canva
- **Presentations**: PowerPoint, Google Slides, Canva
- **Spreadsheets**: Excel, Google Sheets
- **Visualizations**: Tableau, Power BI, Excel charts
- **Graphics**: Canva, Adobe Creative Suite, Figma

### Step 6: Review and Refine

**Review Process**:

1. **Self-Review**
   - Check for completeness
   - Verify accuracy
   - Ensure clarity
   - Confirm formatting

2. **Peer Review**
   - Get feedback from colleagues
   - Check for understanding
   - Validate insights
   - Improve readability

3. **Client Review** (if applicable)
   - Present draft to client
   - Incorporate feedback
   - Finalize deliverable

4. **Final Review**
   - Proofread thoroughly
   - Check all links and references
   - Verify data accuracy
   - Ensure brand consistency

**Review Checklist**:
- [ ] All required sections included
- [ ] Key messages are clear
- [ ] Data is accurate and properly sourced
- [ ] Insights are valuable and actionable
- [ ] Recommendations are specific and feasible
- [ ] Formatting is consistent and professional
- [ ] No errors in grammar, spelling, or punctuation
- [ ] Visuals are appropriate and high-quality
- [ ] Branding is consistent
- [ ] Deliverable meets length requirements

### Step 7: Deliver and Present

**Delivery Methods**:
- Email with PDF attachment
- Shared link (Google Drive, Dropbox, etc.)
- In-person presentation
- Virtual presentation
- Collaborative workspace (Notion, etc.)

**Presentation Tips**:
- **Prepare**: Know the content, anticipate questions
- **Practice**: Rehearse delivery, time yourself
- **Engage**: Make eye contact, encourage questions
- **Adapt**: Adjust based on audience reaction
- **Follow Up**: Send deliverable, answer questions, next steps

**Presentation Structure**:
1. **Opening** (2-3 minutes)
   - Introduce yourself and the deliverable
   - Set the context
   - Outline the agenda

2. **Main Content** (15-30 minutes)
   - Present key findings and insights
   - Walk through analysis
   - Explain recommendations
   - Highlight important data

3. **Q&A** (5-10 minutes)
   - Answer questions
   - Clarify points
   - Discuss implications

4. **Closing** (2-3 minutes)
   - Summarize key messages
   - Reinforce call to action
   - Next steps
   - Thank the audience

## Deliverable Types and Best Practices

### Executive Summary
- **Purpose**: Provide high-level overview for busy executives
- **Length**: 1 page (maximum 2)
- **Focus**: Key findings, recommendations, next steps
- **Tips**: Start with the answer, use bullet points, keep it scannable

### Full Report
- **Purpose**: Provide comprehensive analysis and detail
- **Length**: 10-50 pages (depending on scope)
- **Focus**: Detailed findings, analysis, recommendations
- **Tips**: Use clear sections, include executive summary, provide appendices for detail

### Presentation Deck
- **Purpose**: Present findings verbally to an audience
- **Length**: 10-20 slides (for 30-60 minute presentation)
- **Focus**: Visual storytelling, key messages, engagement
- **Tips**: One idea per slide, use visuals, keep text minimal, include speaker notes

### Analysis Document
- **Purpose**: Provide detailed analysis and insights
- **Length**: 5-20 pages
- **Focus**: Data, analysis, insights, implications
- **Tips**: Show your work, include visualizations, explain methodology

### Recommendations Memo
- **Purpose**: Present actionable recommendations
- **Length**: 2-5 pages
- **Focus**: Problem, analysis, recommendations, rationale
- **Tips**: Be direct, prioritize recommendations, include implementation considerations

### Dashboard
- **Purpose**: Provide interactive data visualization
- **Length**: 1-5 visualizations
- **Focus**: Key metrics, trends, insights
- **Tips**: Keep it simple, highlight key insights, allow for exploration

### Workshop Materials
- **Purpose**: Facilitate interactive sessions
- **Length**: Varies by workshop
- **Focus**: Agenda, activities, discussion guides, handouts
- **Tips**: Include clear instructions, allow for customization, provide takeaways

### Implementation Plan
- **Purpose**: Outline how to implement recommendations
- **Length**: 5-20 pages
- **Focus**: Phases, timelines, resources, risks, metrics
- **Tips**: Be specific, include milestones, assign owners, address risks

### Business Case
- **Purpose**: Justify an investment or decision
- **Length**: 5-15 pages
- **Focus**: Problem, solution, benefits, costs, ROI, risks
- **Tips**: Quantify benefits, include alternatives, address risks, provide clear recommendation

### Financial Model
- **Purpose**: Provide financial analysis and projections
- **Length**: Varies (spreadsheet with multiple tabs)
- **Focus**: Assumptions, projections, scenarios, sensitivity analysis
- **Tips**: Document assumptions, show calculations, include scenarios, validate outputs
